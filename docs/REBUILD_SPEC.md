# CAT-WARS 作り直しの仕様（2026-11-15〜）

実装を引きつぐ人（別のセッション・別のモデル）のための、**決めたこと・数値・合格条件**。
経緯と根拠は知識集 `onokomachi-master-DB` の `techspecs/catwars-rebuild-plan-and-status.md`。
古い設計メモ `docs/CATWARS_DESIGN.md` の経済（自動収入）・陣地（当日リセット）の節は、この仕様が上書きする。

## 0. ゆずれない方針
1. **問題を解くことがゲームを動かす。** 解かずに進める道を作らない（待つ・放置・連打で進まない）。
2. 問題は **SOL の単元アプリと同じ問題・同じ答え方**（`apps/`・`catwars/learn/gradePack.ts`）。1回目のまちがいで×。まちがえても罰はない。
3. **速さを報酬にしない。** 報酬と星は「まちがえずに解けたか」で決める（急いで雑に解くことを得にしない）。
4. 個人の順位表は作らない（学級の合計・自分の記録で見せる）。
5. ガチャ的な要素は SANMON の決まり：確率を画面に出す・天井あり・学習の成果でしか回せない・集めきってもごほうびなし（コンプガチャにしない）。
6. トップ層（1日に長時間）とエンジョイ勢の両方が楽しめる：**上限のない深さ**（難易度・収集・育成）と、**少しでも進む浅さ**（1戦3〜5分・負けても育つ）。
7. 学年はパックで足す（ゲーム本体に4年の単元名を書かない）。

## 1. 戦闘の経済（CW-2・実装ずみ）
- 自動収入なし（`energyPerSec: 0`）。はじめのエナジーは `PLAYER_START_ENERGY = 60`（基本のネコ2回ぶん）。
- エナジーは **問題カード**（`ProblemCards.tsx`）から。手札3枚（やさしい・ふつう・むずかしい）。基準 `QUIZ_BASE_REWARD = 150` × むずかしさの重み（0.75〜1.45）× 連続（×1.0〜2.0）。
- 解いている間、戦闘は止まる。敵をたおした分のエナジー（少額）は残す。
- 星：`starsFor(answered, perfect)`。★3＝8問以上で9割、★2＝5問以上で7割、勝てば★1。
- **合格条件**（`npm run test:balance`。数値を変えたら必ず流す）：
  - 「とかない」（1問も解かない想定プレイヤー）が **全章で勝率0%**
  - 「ふつう」が勝った試合で解いた問題が **平均18問以下**
  - 「にがて」の勝率が 目標±15ポイント（章1〜2：85%／3〜6：70%／7〜8：55%）
- 想定プレイヤー（`scripts/botSim.ts`）：正答率（0.92／0.78／0.58）・人の操作の速さ（**2.5／3.5／4.0秒に1手**。CW-4b で 2.0／3.0／4.5 から差を小さくした：操作の速さは算数の力ではない）・エナジーが足りないときに解く。げきむず では 根気（`maxProblems`）の代わりに カードの まいすう（`cardLimit`）を使う。
- **げきむず の カードの まいすう（CW-4b・2026-11-15）**：
  - **分かったこと**：問題を解いている間は戦闘が止まり、まちがえても何も失わないので、正答率（0.78 と 0.58）は勝率に ほとんど効いていなかった（「ふつう」の正答率だけを 0.58 にしても 100%）。勝率を分けていたのは「1手の速さ」で、「問題を解くことがゲームを動かす」「速さを報酬にしない・正確さを報酬にする」とずれていた。げきむず でも ふつうの子が全章100%勝てた。
  - **決めたこと**：げきむず だけ、1戦で引ける問題カードに まいすうの上限をつける（`TIER_CARD_LIMIT.extreme`。章ごと。`TIER_INFO.extreme.cardLimit` は めやす）。数えるのは 答えを出した カード（「やめて もどる」で答えずに閉じたものは数えない）。**シールドを わる カードは数えない**（割れずに詰むのを防ぐ）。まちがえずに解くと ⚡、まちがえると その1まいは ⚡ なしで終わる＝**正確に解くほど 多く出撃できる**。使いきると手札は出なくなり（「カードを つかいきった！ いまの ネコで がんばれ」）、盤上のネコと のこりの ⚡ で たたかう。ふつう・むずかしい は 上限なし。
  - サポートモード（連敗の救済）では +3／+6（`ASSIST_CARD_BONUS`）。
  - 画面：戦闘の手札の上に「🃏 のこり n まい」、ステージえらびと作戦の画面に「カードは n まいまで。まちがえずに とくほど 有利」。文は「まちがいへの罰」ではなく「正確さへの ごほうび」として書く（せめる言い方をしない）。
  - sim の外（画面と想定プレイヤー）で数える。sim には入れていない（⚡ は これまでどおり `GRANT_ENERGY`）。

## 2. 敵・難易度・やりこみ（CW-3・実装ずみ 2026-11-15）
- **難易度3段**（`campaign.ts` の `TIER_INFO`・`tierDifficulty()`）：各章に ふつう／むずかしい／げきむず。
  - むずかしい＝敵の兵HP×1.35・こうげき×1.1・報酬×1.5・敵の基地に砲台1つ（`battleMaps.ts` の `tierEnemyBase`）・新しい敵を1〜2種類・ボスは4・6・8章（シールド2枚）。
  - げきむず＝HP×1.8・こうげき×1.2・報酬×2.2・砲台2つ＋電撃トラップ1つ・新しい敵がそろう・ボスは全章（シールド3枚）。
  - 開き方：むずかしい＝その章の ふつう をクリア／げきむず＝むずかしい をクリア（`useCampaignStore.isTierUnlocked`）。星・連敗（サポートモード）は段ごと（鍵 `tierKey`＝「ch3:hard」。ふつうは章IDのまま＝前のセーブと同じ）。章の開放と「n/8章クリア」は ふつう だけで数える。星は1章で最大9つ。
  - 出現の速さの倍率は 仕様の ×1.25／×1.5 から出発し、合格条件に合うよう章ごとに決めなおした（`TIER_SPAWN_MULT`）。敵の出現には下限（0.6秒に1体）があり、第1章は速めても手ごたえが変わらないので、兵の強さを足した（`TIER_POWER_MULT`）。
- **脅威レベル**（CW-4a で式を変えた。§3a。CW-4b で係数を 0.99 に）：`threat = round(0.99 × max(0, 手持ちの上位5系統の平均レベル − 章の基準レベル))`（基準＝`CHAPTER_BASE_LEVEL`＋段のぶん 0／12／24）。敵の倍率は §3a の式。下がる方向には はたらかない。ステージえらびと戦闘の上の帯に「脅威 Lv.n」と「+x%」を出す（隠れた調整はしない）。
- **新しい敵**（`ENEMY_TRAIT_NOTE`。ステージえらびに アイコンと たおし方、戦闘中は頭の上に アイコン）：盾持ち（魔法いがい半分・魔法1.5倍）／回復役（2秒ごとに 2.5マスの味方を最大HPの8%）／自爆（ネコは ねらわず施設に つっこむ・1回きり）／空中（近接＝射程2未満で飛行でないネコは とどかない）。空中の敵が出る第7・8章は、さくせんの文で「近接は とどかない。遠距離・魔法を まぜよう」と伝える。
- **ボスのシールド**：割らないとダメージが1割しか通らない。いま盤上にシールドがあると、問題カードの上に4枚めの「🛡️ シールドを わる（ふくしゅう）」カードが出る（`ProblemCards.tsx`）。中身は **その子が まちがえた項目**（`store/useReviewStore.ts`。ふつうのカードで まちがえると入る・50件まで）のうち えらんだ単元のもの。無ければ「むずかしい」帯から。**まちがえずに解けたら** 1枚われて（`BREAK_SHIELD`）、その項目は ふくしゅうから はずれ、ふつうの ⚡ も入る。まちがえても罰はない。ポータルにつないだら「復習の時期が来た項目」（`next_due_ts`）に置きかえる。
- **合格条件**（`npm run test:balance:all`＝3段（`BAND=1`：帯の外も不合格）＋脅威＋正確さ。各 24回。いまの条件と測定は §3b）：
  - 全章×3段で、とかない＝0%。にがての勝率が目標帯（ふつう 85/85/70/70/70/70/55/55、むずかしい −15、げきむず −30。±15ポイント）。
  - 「ふつう」が勝つまでに解く問題：ふつう・むずかしい 平均18問以下、げきむず 24問以下。
  - げきむず：「ふつう」の勝率 50〜90%、かつ「じょうず」が「にがて」より 30ポイント以上高い。むずかしい の「ふつう」の帯は やめた（CW-4b）。
  - 脅威（`THREAT=1`）：§3a。正確さ（`ACCURACY=1`）：§3b。

## 3. 基地・育成・収集（CW-4）

### 3a. 実装ずみ（CW-4a・2026-11-15）：育成・基地の永続化・編成・用語

**育成**（`data/characters.ts`）
- レベルごとに少しずつ強くなる：`levelMult(Lv) = 1 + 0.035×(Lv−1)`（HP・こうげき。Lv10≒1.32・Lv30≒2.0・Lv60≒3.07）。前の Lv10・Lv30 の段差（×1.45・×2.0）はやめた。進化（Lv10・Lv30）は見た目と、あとの「スキルの枠」のために残す。
  sim は `levels`（系統 → レベル）を受け取る（`resolveUnitStats`・`PlayerSetup.levels`）。戦闘中の一時ランクアップはそのまま。
- `MAX_LEVEL = 60`。系統ごとの上限 ＝ `20 + 5×かけら`（60まで）。上限の系統には XP が入らない。
- **かけら**（`learn/shards.ts` の `localShards`。**ポータルにつなぐ前の端末の中だけの数え方**。CW-5 で kit の `sanmonShards` に置きかえる）：
  単元のかけら（0〜8）＝ その単元の項目のうち「まちがえずに3回以上解けた項目」の割合 × 8 を切り捨て。系統のかけら ＝ 結びつけた単元の平均（切り捨て）。
  記録は `store/useStudyStore.ts`（`perfect["単元/skill_id"]`・`todayPerfect`）。戦闘の問題カード（`onAnswered` → `bridge.grantStudyReward`）から足す。
- **系統と単元**（学年パック `gradePack.ts` の `FAMILY_UNITS`。パックに無い系統＝ボスは全単元）：
  魔法＝分数・小数のしくみ／タンク＝わり算の筆算(÷1けた)・(÷2けた)／遠距離＝がい数・倍の見方／爆発＝小数のかけ算とわり算・計算のきまり／飛行＝垂直・平行と四角形／高速＝変わり方調べ／回復＝面積／近接＝直方体と立方体。
- 図鑑（`ArmyRosterScreen`）：上限 Lv.n・💎かけら n/8・上限のときは「つぎの上限：『単元名』を まちがえずに とこう」（いちばん かけらの少ない単元）。
- XP（`data/rewards.ts`）：問題1問（まちがえず・むずかしさ3）で 出撃の5枠に 12、戦闘のあと 出撃させた系統に 勝ち150／負け50。次のレベルまで `round(2.6×Lv² + 30)`（Lv24 まで累計 11,932・Lv60 まで 約178,000）。

**脅威レベル**（`campaign.ts`）：敵の倍率 ＝ `levelMult(基準 + 0.9×育てた分) ÷ levelMult(基準)`（上限 +120%）。「脅威 Lv.n」の n ＝ `round(0.9×育てた分)`。
`THREAT_GROWTH` は 0.75 から始めたが、5章で「にがて」の差が +20 を超えたので 0.9 にした（育てたぶんの1割は そのまま楽になる）。
CW-4b で 0.99 にした（1手の速さを そろえたら「にがて」の +0 の勝率が下がり、0.9 では 第3・4・8章で 差が +21〜+46。0.95／0.97 でも 第3章 +21、1.0 では 第6章 −8 だった）。脅威は レベルだけで決まり、スキルは数えない（§3b）。

**自爆ロボ**：敵AIの兵（`entity.kind` あり）には、同じ subType のネコの `buildingDamageMult` を掛けない（前は ぼむにゃー の ×4 が掛かり、コア1500 が1回で 800 へった）。1回の基本ダメージ 300（章の倍率の前。コアの約2割）。

**基地の永続化**（`data/facilities.ts`・`store/useBaseStore.ts`（鍵 `catwars-base-v2`。前の当日リセットのセーブは読まない））
- 施設は持ちつづける。種類ごとに「持っている数」と「レベル（1〜10。種類ごとに1つ）」。買う・上げるのは 💠（`usePlayerStore` の resources.gold。上限は事実上なし。はじめ 500）。
- レベルの効き目：コア・砲台・電撃トラップ・壁は HP・こうげき ×(1 + 0.1×(Lv−1))（`SimInit.playerBuildings[].mult` で渡す。sim はストアを読まない）。
  兵舎は 持っている数で系統が開く（1：爆発・高速／2：魔法・回復／3：飛行。近接・遠距離・タンクは はじめから。ボスは傭兵召集で 💠）。キャンプは 置いて動いている数だけ 呪文 +1。
  発電所（旧 金山）は 勝ったときの 💠 +5%／個・+1%／Lv（放置の収入は無い。前の「来訪時にまとめて回収」は消した）。
- **その日に動かせる数**（`activeFacilityLimit`）：コアは いつも。戦場に置く施設（砲台・電撃トラップ・壁・キャンプ）は `2 + floor(きょう まちがえずに解いた数 ÷ 5)` 個まで、先に置いた順。止まっているものは 陣地づくりで うすく（💤）出す。兵舎・発電所は置かない施設なので 持っていれば はたらく。
  陣地づくりに「きょう 動かせる施設：n／m　あと k問 まちがえずに とくと +1」（n＝動かせる数、m＝持っている 置く施設の数）。

**編成**（`components/army/FormationScreen.tsx`）：ステージえらび → **出撃メンバー（5枠）** → 陣地づくり → 戦闘。
- 5枠は `useArmyStore.formation`（はじめは 近接・遠距離・タンク・爆発・魔法 のうち開いているもの）。戦闘の下のバーには5つだけ。

## 5. 遠征・対戦（CW-6）
- **週がわりの遠征**：毎週月曜に、種（seed）とルール（例：空中の敵だけ・霧で射程−1・敵の出現2倍）が変わる。学級の合計スコア（星の合計）で目標を目指す。個人の順位は出さない。
- **同時対戦（本命）**：決定的な戦闘の計算（`catwars/sim/`）とロックステップ（`catwars/net/lockstep.ts`）を Supabase Realtime Broadcast に載せかえる（`net/transport.ts` の実装を1つ足す）。
  対戦のエナジーも問題から（2人に同じ問題カードを配る）。SANMON のクラス対戦と同じく、部屋・スタミナ・勝ち負けの記録はサーバ。
- **基地を攻めあう**：友だちの基地の配置（サーバに保存）に、CPU が守る形で攻めこむ。相手は同時にいなくてよい。
